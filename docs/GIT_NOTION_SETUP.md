# Настройка интеграции Git → Оценка → HITL → Notion

Документ описывает процедуру первоначальной настройки и эксплуатации цепочки мониторинга репозиториев и синхронизации с базой данных Notion (Фаза 4, требования GIT-01..GIT-04, NTN-01, NTN-02).

---

## 1. Что делает цепочка

Цепочка обеспечивает регулярный контроль активности по проектам владельца:
- **Автоматическая оценка**: Планировщик еженедельно запускает анализ git-репозиториев рабочих пространств согласно расписанию в персоне.
- **Интерактивная оценка**: Владелец в любой момент может запросить текущий статус проектов командой `/git` в Telegram-боте.
- **Человек в контуре (HITL)**: Запись активности в Notion никогда не производится автоматически. Бот предлагает интерактивную карточку подтверждения:
  - При нажатии **«Подтвердить»** отчет вносится в базу активности Notion.
  - При нажатии **«Отклонить»** действие отменяется, в Notion ничего не записывается.
  - Повторный запуск оценки за ту же дату не создает дублирующих записей.

---

## 2. Что нужно сделать вам

Для включения публикации в Notion выполните следующие шаги:

1. **Создайте базу активности в Notion**:
   - В вашем рабочем пространстве Notion создайте новую базу данных (Database).
   - Настройте необходимые свойства:
     - `Name` — тип **Title** (название записи);
     - `Project` — тип **Relation** (связь с вашей базой проектов);
     - `Date` — тип **Date** (дата отчета активности);
     - `Commits` — тип **Number** (число коммитов за период);
     - `Status` — тип **Select** с обязательными предсозданными опциями: **Активно** и **Застой**.

2. **Подключите интеграцию к Notion**:
   - В настройках Notion (*Settings & Members* -> *Connections*) создайте внутреннюю интеграцию (Internal Integration) и получите секретный токен.
   - Предоставьте интеграции доступ к созданной базе активности и к страницам соответствующих проектов (*Add connections*).

3. **Определите идентификаторы**:
   - Скопируйте 32-значный идентификатор вашей базы данных активности из её URL-ссылки.
   - Скопируйте 32-значные идентификаторы страниц соответствующих проектов из их URL-ссылок.

4. **Задайте переменные окружения**:
   - В вашем локальном файле `.env` на сервере добавьте строки:
     ```bash
     NOTION_API_KEY=ваш_секретный_ключ_интеграции
     NOTION_ACTIVITY_DB_ID=идентификатор_базы_активности
     ```
   - *Важно: значения секретов и ключей в чат не присылаются и хранятся только в защищенном файле `.env`.*

5. **Привяжите проекты в конфигурации персоны**:
   - Для нужных рабочих пространств в файле `config/persona.yaml` укажите свойство `notion_project: "<идентификатор_страницы_проекта>"`.
   - Зафиксируйте файл `config/persona.yaml` через процедуру разового согласованного коммита с флагом `--no-verify`, как это регламентировано политикой безопасности проекта (D-21).

6. **Примените изменения**:
   - Перезапустите сервис `assistant-worker` строго по регламенту `docs/OPS_DEPLOY.md` (`python3 scripts/deploy.py --backup --restart`) после подтверждения готовности.

## 3. Статусы в ответе команды /git

В ответе Telegram-бота по каждому рабочему пространству отображается его текущее состояние:

| Статус | Описание |
|---|---|
| `пропущено: нет remote` | Пространство не содержит настроенного git remote URL или SSH-псевдонима. |
| `пропущено: нет каталога` | Каталог репозитория не найден на файловой системе сервера. |
| `пропущено: не git-репозиторий` | В указанном каталоге отсутствует папка `.git`. |
| `сбой SSH` | Сетевой сбой или отсутствие доступа по SSH при выполнении `git fetch`. |
| `Notion не настроен` | Репозиторий оценен, но в персоне не задан `notion_project` либо не настроен `NOTION_ACTIVITY_DB_ID`. |
| `🔒 NDA: исключено из оценки` | Пространство имеет статус `RESTRICTED_NDA` либо неопределенный допуск. Такие пространства изолированы: они не читаются, не оцениваются моделями LLM и никогда не передаются в Notion. |

## 4. Расписание и порог застоя

Параметры работы задаются в `config/persona.yaml` в блоке `connectors.git_source`:
- `stagnation_days` (по умолчанию `7`) — количество дней без новых коммитов, после которого проекту присваивается статус «Застой».
- `day_of_week` (по умолчанию `sun`) — день недели для автоматической фоновой оценки.
- `hour` (по умолчанию `20`) — час запуска фонового цикла (по часовому поясу сервиса).
- `minute` (по умолчанию `0`) — минута запуска фонового цикла.

## 5. Известные ограничения

- **Версия API Notion**: Используется фиксированная версия API `2022-06-28`.
- **Опции статуса**: Автоматическое создание новых опций в свойстве типа `Select` не гарантируется API, поэтому опции «Активно» и «Застой» должны быть созданы в свойствах базы заранее.
- **SSH-ключи на VPS**: На сервере настроен доступ только к публичным репозиториям по HTTPS/SSH. Приватные репозитории без настроенных ключей в `~/.ssh` вернут статус «сбой SSH».
- **Срок жизни карточки HITL**: Интерактивная карточка в Telegram действительна в течение 24 часов с момента формирования.
- **Кэш сессии команды**: Снимок результатов команды `/git` для формирования карточки хранится в оперативной памяти процесса бота (до 5 последних запросов). При перезапуске сервиса для запроса карточки потребуется повторно вызвать команду `/git`.
- **Сводка после рестарта**: При старте демона фоновый цикл отправляет сводку один раз при наступлении заданного времени.
- **Повтор при сбоях**: При сбое API Notion во время нажатия «Подтвердить» карточка автоматически возвращается в статус ожидания (`pending`), позволяя повторить попытку нажатием кнопки.

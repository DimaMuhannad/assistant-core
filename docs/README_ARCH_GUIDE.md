# README_ARCH_GUIDE.md: Руководство по архитектуре и решениям владельца

## 1. Концепция: Разделение ролей (Worker vs. Brain vs. Interface)
- **Фоновый сервер (Worker):** Непрерывно висит в сети на зарубежном VPS (Сингапур/ЕС), слушает Telegram по MTProto, мониторит сайт с расписанием и почту, скачивает документы, ведет базу SQLite.
- **LLM-бэкенд (Brain):** Вызывается по API (Gemini 2.5 Flash / Pro) только тогда, когда накопились кванты данных или произошло событие, требующее классификации/саммаризации.
- **Планшет (Interface):** Единый командный пункт — просмотр утреннего брифа, утверждение действий кнопками (Human-in-the-loop) и голосовой доступ к календарю через системного ассистента.

## 2. Ключевые архитектурные принципы
- **Read Autonomously, Write with Confirmation:** Сбор и анализ информации происходят в фоне без участия человека. Любое внешнее действие (отправка письма, ответ в чат, удаление событий) требует нажатия кнопки в Telegram-боте.
- **Двухэтапная фильтрация (Map-Reduce):** Сырые логи и сообщения сначала фильтруются детерминированным кодом на Python (хэши, стоп-слова, regex), и только отобранные события отправляются в Gemini API.
- **Трехуровневая память:**
  - Краткосрочная: контекст текущего сеанса.
  - Оперативная (SQLite): события, изменения и файлы за последние 7–30 дней.
  - Постоянный профиль (USER_PROFILE.md): жестко зафиксированные правила, приоритетные каналы, научные интересы и расписание.

## 3. Матрица инфраструктуры
- **Основной хост:** Зарубежный VPS (DigitalOcean Сингапур или Hetzner ЕС) — оплата картой Сингапура, прямой доступ к Gemini API и Telegram MTProto.
- **Доступ к локальным сайтам (РФ):** В случае гео-блокировок со стороны университетского портала в парсер подставляется локальный прокси.

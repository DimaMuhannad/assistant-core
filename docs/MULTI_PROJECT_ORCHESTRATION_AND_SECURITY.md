# Архитектурная спецификация: Оркестрация мультирепозиторной разработки GitHub (2 аккаунта), единые стандарты и политики безопасности проектов

## 1. Назначение и контекст
Настоящий документ регламентирует архитектуру, инфраструктурную изоляцию и стандарты агентной разработки для распределенной экосистемы проектов **Дмитрия Александровича Попова**.

Цели регламента:
1. **Мультиаккаунтная оркестрация GitHub**: Надежное разделение личных/академических репозиториев (`DimaMuhannad`) и закрытых корпоративных репозиториев ООО «Тидекс» (коммерческая тайна, NDA).

3. **Раздельный контроль в Notion**: Двусторонняя связь инженерных задач (`Issues DB`) с проектами (`Projects DB`), фильтрация досок и управление через CLI `notion_dev.py`.
4. **Контроль политики безопасности и Security Tile («Плитка безопасности»)**: Многоуровневый щит предотвращения утечек учетных данных, изоляция контекстов и визуальный мониторинг безопасности в Antigravity Studio.

### 2.3. Конфигурация SSH (`~/.ssh/config`)
Для исключения путаницы с правами доступа и ключами каждый аккаунт авторизуется через выделенный Host Alias:

```ssh-config
# ==============================================================================
# 1. Личный / Академический GitHub (DimaMuhannad)
# ==============================================================================
Host github.com-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_personal
    IdentitiesOnly yes

# ==============================================================================
# 2. Корпоративный GitHub ООО «Тидекс» (Tydex Optics)
# ==============================================================================
Host github.com-tydex
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_tydex
    IdentitiesOnly yes
```

При клонировании корпоративного репозитория URL формируется через алиас:
`git clone git@github.com-tydex:tydex-optics/golay-cell-controller.git`

### 2.4. Условная маршрутизация Git (`includeIf`)
Глобальный конфиг `~/.gitconfig` автоматически подставляет корпоративного автора и SSH-команду при входе в директорию `/opt/work-tydex/`:

```gitconfig
# ~/.gitconfig (Глобальный)
[user]
    name = Dmitry Popov
    email = brattri3@gmail.com

# Автоматическое переключение для репозиториев Тидекс
[includeIf "gitdir:/opt/work-tydex/"]
    path = /opt/work-tydex/.gitconfig_tydex
```

Содержимое файла `/opt/work-tydex/.gitconfig_tydex`:
```gitconfig
[user]
    name = Dmitry Popov
    email = d.popov@tydex.ru
[core]
    sshCommand = ssh -i ~/.ssh/id_ed25519_tydex -F /dev/null
```

> **Гарантия безопасности:** При работе в папке `work-tydex` невозможно случайно закоммитить код под личным email или запушить его с личным ключом.

## 3. Перевод разработки на «Единые рельсы» (Unified Dev Rails)

Любой агентный проект экосистемы стандартизируется по 4 базовым направлениям:

### 3.1. Стандарт директив агента (`GEMINI.md` / `AGENTS.md`)
В корне каждого репозитория размещается файл правил, содержащий:
- Четкое определение роли агента и архитектурных границ модуля.
- **Языковой протокол:** Внутренние мысли (thinking) и комментарии в коде — на английском/русском, но **любой текст, адресованный пользователю в чат или Telegram — строго на русском языке**.
- **Стандарты оформления:** Визуальные эмодзи-загороловки жирным шрифтом, запрет локальных ссылок с протоколом `file:///`, обязательные diff-блоки со статусом Git.
- **Архитектурные принципы:** Occam's Razor, KISS, YAGNI, Boy Scout Rule, Hanlon's Razor.

### 3.2. Атомарный Git Workflow и Quality Gates
- **Префиксы коммитов:** `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `infra:`.
- **Обязательный тест-гейт:** Ни один коммит не считается завершенным без прогона тестового набора (`pytest` или `vitest`).
- **Контроль регрессии:** При падении тестов действует правило 3 итераций: если за 3 попытки баг не устранен — фиксация блока через `notion_dev.py block` и возврат задачи в `Backlog`.

### 3.3. Сессионный след (Session Provenance)
Каждая выполненная задача оставляет стандартизированный след в теле карточки задачи в Notion:
- `[Changeset]`: Что физически изменилось в архитектуре файлов.
- `[Design Decisions]`: Обоснование принятых решений (KISS/YAGNI).
- `[Quality Gates Status]`: Результаты выполнения тестов и линтеров.
- `[Technical Debt Introduced]`: Зафиксированный технический долг.

### 4.2. Управление через CLI `scripts/notion_dev.py`
Утилита `scripts/notion_dev.py` поддерживает фильтрацию и привязку по проектам:

```bash
# Просмотр задач по проекту Тидекс
python3 scripts/notion_dev.py list --project tydex

# Просмотр задач по AI Studio
python3 scripts/notion_dev.py list --project ai

# Создание задачи с явной привязкой к проекту
python3 scripts/notion_dev.py create "Драйвер АЦП для ячейки Голея" \
    --project tydex \
    --module "Domain Context (ГУАП/Тидекс)" \
    --priority "P1 - High"
```

## 5. Политика безопасности и «Плитка безопасности» (Security Tile)

### 5.1. Архитектурная необходимость изоляции проекта «Тидекс»
Проект сектора оптических приборов ООО «Тидекс» защищен режимом коммерческой тайны и NDA:
- Алгоритмы калибровки датчиков, драйверы ячеек Голея и математические модели спектрометров являются интеллектуальной собственностью компании.
- Случайная публикация закрытого кода в личный аккаунт GitHub или утечка API-ключей в публичные логи наносит ущерб бизнесу и несет юридические риски.

### 5.2. Pre-Commit Secret Shield (`scripts/security_shield.py`)
Автономный скрипт контроля безопасности, подключаемый как Git Pre-Commit Hook или запускаемый в CI:
- **Сканирование секретов:** Поиск приватных ключей (`RSA`, `OPENSSH`), персональных токенов (`ghp_`, `github_pat_`), Google Gemini API ключей (`AIzaSy...`), токенов Telegram-ботов и Notion API.
- **Защита от утечки файлов:** Блокировка коммита файлов `.env`, `credentials.json`, `token.json`, `*.session`, `*.pem`, `*.key`.
- **Проверка Origin Remote:** Для проектов с префиксом `tydex` проверяется, что Git Remote не указывает на публичный аккаунт `DimaMuhannad`.
- **Контекстный Air-Gap:** Проверка отсутствия упоминания закрытых ноу-хау Тидекс в кодовой базе публичных проектов.

Команда ручного аудита:
```bash
python3 scripts/security_shield.py /opt/chat-app
```

### 5.3. Плитка безопасности (Security Tile) в Web Studio (`chat-app`)
В веб-интерфейсе Antigravity Studio (вспомогательная панель и верхний статус-бар) формируется интерактивная **Плитка безопасности (Security Tile)**:

1. **Индикатор допуска проекта (Security Clearance Badge):**
   - 🟢 `PUBLIC / ACADEMIC` (Личные проекты, репозитории ГУАП).
   - 🔴 `RESTRICTED / NDA AIR-GAP` (Проекты ООО «Тидекс»).
2. **Монитор защиты от утечек (Secret Leak Guard):**
   - Отображение статуса прекоммит-хука и сканера секретов (`Passed` / `Alert`).
3. **Remote Safeguard:**
   - Валидация целевого хоста для `git push` (предупреждение при попытке пуша в неавторизованный remote).
4. **Контекстный брандмауэр агента (Agent Air-Gap):**
   - Блокировка чтения локальных директорий `/opt/work-tydex` субагентами, запущенными в сессиях публичных проектов.

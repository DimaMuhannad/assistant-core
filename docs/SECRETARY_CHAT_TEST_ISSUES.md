# Реестр выявленных проблем и дефектов диалогового секретаря

Данный документ ведется в процессе комплексного тестирования взаимодействия с персональным секретарем-референтом (`@opd_guap_popov_bot` / `SecretaryDialogEngine` / `FastIntentRouter`).

---

## 📌 Выявленные проблемы и анализ архитектурных причин

### 🔴 Проблема №1 (Задача в Notion: #23, Ready for Dev): Превышение бесплатной квоты Gemini 3.8/3.7 Flash (429 Resource Exhausted) и деградация задержки классификатора и диалога до 30–42 сек
- **Компонент:** `FastIntentRouter` (`src/brain/intent_router.py`), `SecretaryDialogEngine` (`src/brain/secretary_dialog.py`), конфигурация `.env` (`GEMINI_MODEL=gemini-3.8-flash`)
- **Симптом при живом тестировании (Этап 1):**
  При отправке реальных запросов ответы системы успешно генерируются и доставляются в Telegram Дмитрию Александровичу, но общее время ответа составляет от **31.5 до 42.2 секунд** вместо целевых 1.5–2.0 секунд!
  - Запрос 1 («Покажи табель тидекс»): 31 477 мс (sent_id: 56)
  - Запрос 2 («Какие у меня сегодня пары в ГУАП и во сколько?»): 42 167 мс (sent_id: 57)
  - Запрос 3 («Сколько часов мне осталось до закрытия месячной нормы в Тидекс?»): 35 425 мс (sent_id: 58)
- **Анализ мыслительного процесса и корневой причины (Трейс вызовов):**
  1. `FastIntentRouter`: сначала вызывает `gemini-3.5-flash`, зависает на 5 сек таймаута; затем пробует `gemini-3.8-flash` и мгновенно получает `429 RESOURCE_EXHAUSTED` (суточный лимит 20 запросов на бесплатном ключе исчерпан); только на 3-й попытке вызывает `gemini-3.5-flash-lite`, который отрабатывает за **800 мс**!
  2. `SecretaryDialogEngine`: аналогично пробует `gemini-3.5-flash` (таймаут 25 сек!), затем `gemini-3.8-flash` (ошибка 429), и лишь на 3-й попытке обращается к `gemini-3.5-flash-lite`, который формирует безупречный, детальный ответ за **1.3 сек**!
  3. **Вывод:** Сам генеративный ответ формируется за 1.3–2.0 сек, а 30+ секунд теряются на переборе недоступных или таймаутящих моделей в цепочке кандидатов.
- **Статус в Notion:**
  Зарегистрирована задача **#23** со статусом `Ready for Dev` (Milestone: Phase 10) без перехода к исполнению.
- **Предлагаемое решение для бэклога Notion:**
  1. Сделать `gemini-3.5-flash-lite` приоритетной первой моделью в цепочке кандидатов как для классификатора, так и для генератора диалога.
  2. Сократить таймаут первой попытки в диалоге с 25 сек до 4.0 сек.
  3. Исключить модели `gemini-3.8-flash` и `gemini-3.7-flash` из регулярного роутинга на бесплатных тарифах при обнаружении 429 ошибки (с кулдауном на 1 час).

### 🟡 Проблема №2: Предупреждение Google GenAI SDK о прямом вызове генерации в фоновом цикле
- **Компонент:** `google-genai` / `AsyncModels.generate_content`
- **Симптом:**
  В логах выводятся предупреждения:
  `Direct use of automatic function calling (AFC) in AsyncModels.generate_content is not recommended. Instead, we recommend to use AFC in AsyncChat.send_message.`
- **Анализ причины:**
  SDK `google-genai` версии 1.x рекомендует использовать интерфейс `AsyncChat` для многошаговых диалогов или явно отключать AFC в параметрах `GenerateContentConfig`.
- **Предлагаемое решение для бэклога Notion:**
  Оптимизировать конфигурацию вызовов в `SecretaryDialogEngine` и `FastIntentRouter` с явным указанием `tool_config`.

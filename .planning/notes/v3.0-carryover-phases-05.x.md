### Phase 05.1: Пересмотр карточек и сводка состояния (INSERTED)

**Goal:** Владелец за несколько секунд видит состояние почты, проектов, задач, долгов и недоработанного времени по табелю, а бот не шумит: все существующие карточки, уведомления, меню, брифинги и табло пересмотрены и сокращены до нужного.
**Requirements**: TBD (формулируются в discuss-phase)
**Depends on:** Phase 5
**Context:** `.planning/notes/proactive-owner-picture.md` (пункт 7); инвентаризация 2026-10-19: ~10 типов уведомлений (`send_*` в `src/notifier/`), ~70 мест с кнопками (`bot_handler.py`, `telegram.py`, `live_ticker.py`), 36 префиксов callback, утренний брифинг, вечерний дайджест, `/ticker`
**Success Criteria** (черновик, уточняется в discuss-phase):
  1. Аудит UX: перечень всех карточек и UI-элементов с оценкой «оставить / объединить / убрать / упростить» по коду и по живой проверке с владельцем; решения владельца записаны.
  2. Единая короткая сводка состояния (почта, проекты, задачи, долги, табель) по команде и в брифинге: одна строка на область, детали по кнопке.
  3. Шум снижен измеримо: число сообщений бота в день и число кнопок в типовых карточках до и после; повторяющиеся и дублирующие уведомления убраны или сгруппированы.
  4. HITL-карточки сохраняют подтверждение для необратимых действий (`ConfirmationStore` + `resume_action`); упрощение не обходит подтверждение.
  5. VERIFICATION.md доказывает достижимость из рантайма (команда бота, задачи `src/main.py`). Рестарт `assistant-worker` — только по разрешению владельца, смоук OPS-01 пройден.

### Phase 05.2: Проактивная картина владельца (INSERTED)

**Goal:** Ассистент сам, без запроса, находит проблемы владельца по уже собранным данным (почта, Telegram, задачи и напоминания, LMS, табель, расписание и календарь) и приносит их с готовым действием, а не просто перечнем источников.
**Requirements**: TBD (формулируются в discuss-phase; поглощает UXQ-04 из 999.11)
**Depends on:** Phase 05.1 (проблемы выводятся в уже очищенный интерфейс и единую сводку состояния)
**Context:** `.planning/notes/proactive-owner-picture.md` (решения владельца 2026-10-19)
**Success Criteria** (черновик, уточняется в discuss-phase):
  1. Детерминированные правила находят четыре класса проблем: сроки и долги, конфликты времени и нагрузки, важное, утонувшее в потоке, и тренды за недели, а также «проект требует внимания» (давно нет коммитов или активности, близкий срок; по данным Phase 4, расширяется в 05.3). У каждой проблемы есть состояние (новая / показана / отложена / решена), повторов нет.
  2. Карточка «проблема → готовое действие» (например, черновик ответа) с кнопками «Отправить / Изменить / Отложить»; любое внешнее действие — только через HITL (`ConfirmationStore` + `resume_action`).
  3. Срочное (срок сегодня или завтра, конфликт в ближайшие часы) приходит сразу, с дневным лимитом и тихими часами; остальное — блоком «Картина дня» в утреннем брифинге; тренды — в недельном обзоре.
  4. Сбор из Telegram углублён: ассистент опросом спрашивает, за какими чатами, группами и каналами следить, а какие игнорировать; замечает новые чаты и спрашивает о них; выбранные чаты индексируются (не только вручную внесённые `monitored_sources`).
  5. VERIFICATION.md доказывает достижимость из рантайма через реальные задачи `src/main.py` и бот. Рестарт `assistant-worker` — только по разрешению владельца, смоук OPS-01 пройден.

### Phase 05.3: Проекты из диалога в Notion (INSERTED)

**Goal:** Владелец рассказывает боту обычными фразами о себе, новых задачах и проектах; ассистент запоминает это, разворачивает проект в Notion в стиле проектной деятельности, подключает к проекту репозиторий и следит, какой проект требует внимания.
**Requirements**: TBD (формулируются в discuss-phase)
**Depends on:** Phase 05.2 (поиск проблем и карточки с действием; сигнал «проект требует внимания» живёт в общем движке 05.2)
**Context:** `.planning/notes/proactive-owner-picture.md` (пункт 6); основа — цепочка Git → оценка → HITL → Notion из Phase 4 (`src/connectors/notion/client.py`, `SshGitProvider`)
**Success Criteria** (черновик, уточняется в discuss-phase):
  1. Рассказ владельца о себе, задаче или проекте в чате (текстом или голосом) сохраняется как факты памяти и записи проекта; таблица `projects` наполняется из диалога, а не из засева `_seed_initial_data_if_empty`.
  2. Новый проект разворачивается в Notion как проектная структура (цель, этапы, задачи, сроки) только после HITL-карточки; отмена ничего не создаёт.
  3. Репозиторий подключается к проекту фразой в диалоге; проект попадает в оценку хода проектов из Phase 4.
  4. Правило «проект требует внимания» (давно нет коммитов или активности, близкий срок, зависшие задачи) подаёт сигнал в движок проблем 05.2: в «Картину дня» и, при срочности, сразу.
  5. VERIFICATION.md доказывает достижимость из рантайма (бот → `intent_router`/`SecretaryDialogEngine` → Notion через HITL). Рестарт `assistant-worker` — только по разрешению владельца, смоук OPS-01 пройден.

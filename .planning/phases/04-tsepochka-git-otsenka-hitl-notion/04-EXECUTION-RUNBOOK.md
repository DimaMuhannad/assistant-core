# Фаза 4: runbook исполнения для агента agy

Решение владельца (2026-10-11): код фазы 4 пишет agy. У agy нет команд GSD, скиллов и инструмента Agent, поэтому весь порядок работы описан здесь. Агент не видит историю чата, всё нужное лежит в файлах.

## 0. Роли

| Кто | Что делает |
|---|---|
| **agy** (профиль `gsd-executor`, для тестов `test-writer`, для docs `docs`) | Правит файлы строго по одному плану за запуск. Тесты и гейт не запускает: в клетке нет `.venv`, БД и git-истории. |
| **Claude** | Запускает agy через `/opt/chat-app/scripts/agy_task.sh`, читает патч целиком, гоняет тесты и `python3 scripts/gate.py`, коммитит, правит защищённые пути, ведёт планы 04-02, 04-11, 04-13. |
| **Владелец** | Отвечает на чекпоинты планов 04-11 и 04-13. |

Агент никогда не коммитит и не запускает `agy` рекурсивно.

## 1. Что прочитать агенту перед каждым планом (в таком порядке)

1. `/opt/assistant-core/CLAUDE.md` и `/opt/assistant-core/.claude/CLAUDE.md`: стек, NDA air-gap, HITL, запреты.
2. `.planning/phases/04-tsepochka-git-otsenka-hitl-notion/04-CONTEXT.md`: решения D-01..D-14, они не пересматриваются.
3. `04-PATTERNS.md`: аналоги в коде и фрагменты, по которым пишется новый код.
4. `04-VALIDATION.md`: какие тесты и команды относятся к каким требованиям.
5. Нужный `04-NN-PLAN.md` целиком, включая `<threat_model>` и «Artifacts this phase produces».
6. Файлы из `<read_first>` каждой задачи, до любой правки.

Копия клетки содержит только закоммиченные файлы. Если `.planning/` в клетке нет, Claude вставляет тексты пунктов 2–5 прямо в задачу.

## 2. Правила исполнения плана

- Задачи идут по порядку. Задача считается сделанной, когда выполнены все пункты её `<acceptance_criteria>` по тексту кода. Команды из `<verify>` запускает Claude, и красная команда отправляет задачу на доработку.
- Править только файлы из `files_modified` плана. Любой другой файл: остановиться и написать об этом в отчёте.
- В `<action>` указаны точные идентификаторы. Их нельзя переименовывать и «улучшать».
- Комментарии и тексты для пользователя: по-русски. Логи: `logger.warning("... %s", x)`, без f-строк, без `print`.
- Новые зависимости запрещены. Файлы `data/assistant.db`, `.env`, `credentials.json`, `token.json` не открываются.
- Допуск рабочего пространства (`git_chain_workspaces`) проверяется до любого git, LLM или Notion. Это инвариант фазы, сомнение трактуется как отказ.
- Формат ответа агента: список изменённых файлов, по одной строке на пункт acceptance_criteria («выполнено / не выполнено + файл:строка») и список отклонений от плана. Лимит: 60 строк.

## 3. Где Claude вызывает независимых исполнителей

Одна задача `agy_task.sh run --repo /opt/assistant-core --mode edit` соответствует одному плану. Планы с `files` больше 5 дробятся по задачам, потому что agy ненадёжно правит много файлов за раз (бывал SUCCESS при 1 файле из 8).

Независимые проверки (отдельные запуски без общего контекста):
- **После волны 2:** ревью допуска. Агент `reader` получает патчи 04-01 и 04-05 и ищет путь, по которому NDA или неизвестный допуск достигает git, LLM или Notion.
- **После волны 5:** верификатор достижимости. `reader` получает `src/main.py`, `bot_handler.py` и тесты 04-10 и подтверждает, что `git_progress_job`, `Command("git")` и колбэки `ntn:*` реально доступны из рантайма. Ответ сверяет Claude.
- **Конец фазы:** Claude (не agy) пишет `04-VERIFICATION.md` и `SUMMARY.md` по правилу «Phase hygiene».

## 4. Цикл Claude на каждый план

1. Запуск: `/opt/chat-app/scripts/agy_task.sh run --repo /opt/assistant-core --mode edit --task-file <файл задачи>`. Только через обёртку, `agy` напрямую запрещён.
2. `agy_task.sh diff <JOB_ID>`, чтение патча целиком, сверка с планом и `files_modified`.
3. `git -C /opt/assistant-core apply <патч>`, затем команды `<verify>` плана.
4. `python3 scripts/gate.py` после каждой волны. Красный гейт: задача возвращается agy с текстом ошибки, не более двух попыток, потом Claude правит сам.
5. Атомарный коммит с трейлерами проекта, затем `agy_task.sh clean <JOB_ID>`.
6. SUMMARY плана `04-NN-SUMMARY.md` пишет Claude.

## 5. Остановки и запреты

- Планы 04-11 и 04-13 имеют `autonomous: false`: стоп до ответа владельца.
- `assistant-worker.service` не перезапускается без явного «да», только через `python3 scripts/deploy.py --backup --restart`.
- Тексты задач для agy не содержат секретов и содержимого NDA-документов. Адаптер при их обнаружении откажет с кодом 3 или 4, обходить отказ нельзя.
- Цель 100% прохождения тестов: пропуски, xfail и deselected делают гейт красным.
- Если план требует решения, которого нет в CONTEXT/RESEARCH, агент останавливается и пишет вопрос в отчёте. Выдумывать нельзя.

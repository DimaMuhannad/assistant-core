# Задание для /gsd-quick в chat-app: адаптер cross-AI запускает гейт целевого репозитория (GATE-05, D-15)

Файл целиком передаётся `/gsd-quick` в сессии, открытой в `/opt/chat-app`. Сам план 01-08 репозиторий chat-app не меняет: он только пишет это задание. Переключение и пробный прогон выполняет план 01-09 (assistant-core, фаза 1 «Собственный гейт качества»).

## 1. Заголовок и контекст

**Адаптер cross-AI запускает гейт целевого репозитория (GATE-05, D-15).**

В фазе 1 проекта assistant-core появился собственный гейт `/opt/assistant-core/scripts/gate.py` (десять строк по assistant-core и assistant-shared, итог «ЗЕЛЁНЫЙ»/«КРАСНЫЙ»). Решение D-15: общий `scripts/gate.py` chat-app не трогается; со стороны chat-app меняется только адаптер `scripts/agy_cross_ai.sh`.

## 2. Текущее поведение

Блок `# ---------- gate ----------` в `scripts/agy_cross_ai.sh` всегда запускает `python3 "$SCRIPT_DIR/gate.py"` с рабочим каталогом `"$SCRIPT_DIR/.."`, то есть гейт chat-app, независимо от `--repo`. Для `--repo /opt/assistant-core` он не знает про новые строки гейта assistant-core и даёт ложную уверенность (Pitfall 7 из исследования фазы 1).

## 3. Требуемое поведение (строго по приоритету)

1. Если задана переменная `AGY_GATE_CMD` (тестовая подмена): запускается она, как сейчас, с рабочим каталогом `"$SCRIPT_DIR/.."`.
2. Иначе, если существует файл `"$TOP/scripts/gate.py"` (`$TOP` - корень целевого репозитория из `--repo`): запускается `python3 "$TOP/scripts/gate.py"` с рабочим каталогом `"$TOP"`.
3. Иначе откат на гейт chat-app: `python3 "$SCRIPT_DIR/gate.py"` с рабочим каталогом `"$SCRIPT_DIR/.."`.

Для самого chat-app результат прежний (`$TOP/scripts/gate.py` и `$SCRIPT_DIR/gate.py` - один и тот же файл).

Эскиз, не готовый код (из исследования фазы 1, раздел «Хвост адаптера»):

```bash
if [ -n "${AGY_GATE_CMD:-}" ]; then GATE=("$AGY_GATE_CMD"); GATE_DIR="$SCRIPT_DIR/.."
elif [ -f "$TOP/scripts/gate.py" ]; then GATE=(python3 "$TOP/scripts/gate.py"); GATE_DIR="$TOP"
else GATE=(python3 "$SCRIPT_DIR/gate.py"); GATE_DIR="$SCRIPT_DIR/.."; fi
( cd "$GATE_DIR" && exec "${GATE[@]}" ) < /dev/null > "$GATE_LOG" 2>&1 &
```

Безопасность выбора: `scripts/gate.py` целевого репозитория входит в список защищённых путей адаптера (`PROTECTED` в `helper.py`), поэтому агент не может подменить гейт до запуска.

## 4. Файлы для изменения

- `scripts/agy_cross_ai.sh`: блок gate; комментарий в шапке про выбор гейта (строка про `AGY_GATE_CMD` остаётся, добавить описание приоритета); текст SUMMARY (сейчас «Гейт качества (`python3 scripts/gate.py`) завершился с кодом 0») не должен жёстко утверждать, какой именно репозиторий проверен, достаточно «Гейт качества целевого репозитория завершился с кодом 0» с путём журнала.
- `backend/tests/test_agy_cross_ai.py`: два новых теста (песочница `sandbox` уже кладёт в репозиторий заглушку `scripts/gate.py`, а `AGY_GATE_CMD` задаёт подмену):
  1. репозиторий со скриптом `scripts/gate.py` и БЕЗ `AGY_GATE_CMD` запускает именно этот скрипт (заглушка пишет в журнал вызовов свой путь и рабочий каталог; проверить каталог `$TOP`);
  2. репозиторий без `scripts/gate.py` откатывается на гейт рядом с адаптером; для этого в тесте адаптер копируется во временный каталог вместе с заглушкой `gate.py`, чтобы не запускать настоящий гейт chat-app.
- `.claude/skills/agy-delegate/SKILL.md`: строки про гейт (около строк 21, 87, 150) описывают «гейт целевого репозитория» (`scripts/gate.py` целевого репозитория, при его отсутствии гейт chat-app), вместо «гейт покрывает только их».

## 5. Ограничения (обязательные)

- `scripts/gate.py` chat-app НЕ менять (D-15).
- Список защищённых путей адаптера (`PROTECTED`) не ослаблять и не сокращать.
- Сохранить поведение: отказ при грязном дереве вне `.planning/` (код 10), откат патча при красном гейте (15), отказ при защищённых путях (12), отсутствие автокоммита.
- Новых зависимостей не добавлять.
- Секреты и адреса e-mail в тексты не вставлять.

## 6. Проверка перед коммитом

1. `cd /opt/chat-app && /opt/chat-app/backend/.venv/bin/pytest backend/tests/test_agy_cross_ai.py` - зелёный, включая два новых теста.
2. Полный `/opt/chat-app/backend/.venv/bin/pytest backend/tests` из `/opt/chat-app` - зелёный.
3. Общий гейт chat-app `python3 scripts/gate.py` из `/opt/chat-app` даёт «ИТОГ: ЗЕЛЁНЫЙ» (он проверяет assistant-core и assistant-shared как потребитель).
